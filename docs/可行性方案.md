## 4. 显示与传输设计（核心，已实测）

### 4.1 连接初始化序列

```
1) 打开 /dev/ttyACM0：raw 模式，115200，断言 DTR/RTS（与 pyserial 行为一致）
2) 握手：发 00 4D 53 4E 43 4E (NUL+MSNCN)  -> 设备回显同样内容
3) （可选）读 SFR 寄存器表：0x0100 起 256 字节，命令 00 30 00 <addrH> <addrL> 00
4) （可选）LCD_State(0)：02 03 0A 00 00 00
5) 进入页面时发一次 LCD_ADD(0,0,160,80)：
      02 00 00 00 00 00  |  02 01 00 A0 00 50  |  02 03 07 00 00 00
   -> 设备回显 02 03 07 ... 表示显示区域已就绪
```

**关键：LCD_ADD 只在进入页面/改变区域时发一次，之后连续发帧时绝不再发。**
实测中"每帧都重发 LCD_ADD"会让固件解析错乱、停止读取数据（只能断电恢复）。

### 4.2 帧数据格式（压缩编码，照搬 Screen_Date_Process）

一帧 = 12800 个像素（160×80），按 128 像素（256 字节）为一页，共 100 页：

```
每页：
  a) 把 128 个 RGB565 像素两两打包成 64 个 uint32：
        cmp[k] = (pixel[2k] << 16) | pixel[2k+1]
  b) 找出本页出现次数最多的 cmp 值作为背景色 bg
  c) 发送： 02 04 + 4 字节(bg)          <- 设置本页底色（大端）
  d) 仅对本页与底色不同的项发送：
        04 k + 4 字节(cmp[k])           <- k 为 0..63
  e) 发送： 02 03 08 01 00 00           <- 提交本页（写入 256 字节）
收尾（可选）：02 03 09 00 00 00
```

- 大端拆字节：[(v>>24)&255, (v>>16)&255, (v>>8)&255, v&255]
- RGB565：((R&0xF8)<<8) | ((G&0xFC)<<3) | ((B&0xF8)>>3)
- 纯色整屏：每页仅 12 字节 -> 整帧约 1.2 KB（未压缩格式要 39 KB，**压缩约 32 倍**）

### 4.3 实测性能

| 项目 | 数值 |
| --- | --- |
| 单帧耗时（压缩后） | **0.105 – 0.117 秒** |
| 单帧数据量（含动态横条的测试画面） | 1,680 – 5,040 字节 |
| 纯色整屏帧 | 1,200 字节 |
| 未压缩整屏帧（39,006 字节） | 0.11–0.13 秒（可用，但不推荐） |
| 连续刷新 | **120 帧 / 128 秒 / 1Hz / 0 失败** |
| 理论刷新上限 | 约 8 fps（按单帧 0.12 秒估算） |

实际界面（数字 + 进度条 + 曲线）预计每帧 1–3 KB、耗时约 0.11 秒，**1Hz 刷新余量充足，2–5Hz 亦可**。

### 4.4 设备行为特征（重要）

| 特征 | 说明 |
| --- | --- |
| 待机态 | 每 100 ms 发一次 00 4D 53 4E 30 31（10Hz），并回显所有指令 |
| **显示态** | 开始接收帧数据后进入显示态：**心跳停止、所有指令不再回显**（正常现象，不是故障） |
| 显示态存活判断 | 只能用"写入是否被消费"判断：TIOCOUTQ 归零且写入耗时正常 |
| 串口关闭 | 端口关闭后设备回到待机态（恢复 10Hz 心跳） |
| 卡死特征 | TIOCOUTQ 长期不为 0（设备不再读取 USB OUT），只能**物理断电**恢复 |
| 已知触发卡死的错误用法 | 每帧重发 LCD_ADD；在等待像素数据期间插入其它类型命令；写入被截断 |

### 4.5 渲染方案（路由器侧，零依赖）

- 自建 RGB565 帧缓冲：12800 个 uint16 的数组
- 自建点阵字库（8×16、5×7），无需 PIL/numpy
- 图元：矩形、进度条、柱状曲线
- 脏页优化：值未变的页只发 12 字节底色
- 防烧屏：每 30 秒整体偏移 1 像素（可选）

## 8. 风险与对策

| 风险 | 等级 | 对策 |
| --- | --- | --- |
| 固件卡死（不再读取数据） | 中 | 严格遵守：LCD_ADD 只发一次；每帧数据必须完整写出；不在帧中间插入其它命令；加超时保护 |
| 显示态无法用回显判断存活 | 中 | 以 TIOCOUTQ + 写入耗时判断；连续异常则重开端口并重发 LCD_ADD |
| 卡死后无法软件恢复 | 中 | USB authorized 软复位无效，需物理断电；软件尽量避免触发，并在日志中明确提示 |
| 串口节点名变化 | 低 | 按 VID/PID 1a86:fe0c 扫描或加 udev 规则 |
| 串口被占用 | 低 | 启动时检测并告警（单进程独占） |
| USB 供电/线材 | 低 | 直插主机口，避免 Hub；监控掉线次数 |
| 只有 soc-thermal 温度源 | 低 | 无则显示 -- |
| 屏幕方向 | 低 | 支持 LCD_State 配置（0=正向） |
| Python 常驻内存 | 低 | 约 10–25 MB，可忽略 |
